# 泊岸 Harbor v0.2：原生启动器界面研究与设计规范

研究日期：2026-11-22。本文只包含公开产品资料与泊岸自身的设计决策，可进入公开仓库。示意标题均为虚构样例。

## 结论

保留「顶部搜索 + 左侧项目 + 右侧列表」；把首版较高的入口块收紧为两行列表。名称是视觉中心，验证状态只占一个小标签，解释与次要操作在需要时出现。设置集中为「常规 / 外观」，提供系统外观、点缀色、密度和登录启动，继续使用中文与系统字体。

目标不是复制通用启动器的全部功能。泊岸只整理用户手动保存的工作入口，继续让原生 ChatGPT 承担聊天。

| --- | --- | --- | --- |
| 主面板 | 720 × 500 | 同尺寸 | 可在 680–760 宽内调整；保持当前任务信息稳定 |
| 搜索栏 | 高 56 | 高 52–56 | 左右 18–20；可用输入宽度至少 300 |
| 项目侧栏 | 宽 164–172 | 同宽 | 项目行 32–34；标题截断不推挤右侧内容 |

## 搜索与项目范围

1. 首次打开默认「所有入口」，搜索框聚焦；以后呼出仍聚焦搜索。
2. placeholder 明确为「搜索项目或入口」。若搜索仅限当前项目，改为「在当前项目中搜索…」，并在列表顶栏显示项目名称。
3. 有文本时显示原生清除按钮。清除恢复当前范围，扩大范围需要明确的「搜索所有入口」。
4. 结果同时匹配入口名称与项目名称。不要拿聊天 UUID 或长 URL 当主要搜索内容。
5. 当查询或范围改变导致当前选中项不可见，选择同步到可见结果，避免 Return 打开与高亮不一致的入口。
6. `⌘F` 聚焦搜索；`↑↓` 选择；Return 执行当前项主动作。文本输入法候选、表单和普通按钮保留原生键盘处理。

搜索排序、模糊别名和使用频率学习都不需要本轮额外实现。

## 列表状态与动作

### 每行只承担辨认与选择

- 第一行：入口名称；末尾状态与主动作区。
- 第二行：项目名（仅所有入口视图需要）和来源。项目视图避免重复项目名。
- 默认未选中行不展示大按钮排布；选中行突出「打开 / 验证 / 说明」之一。鼠标悬停可显示更多操作按钮，但键盘和 VoiceOver 同样必须能访问。
- 收藏可使用细小星标表达。更改收藏、编辑、复制链接放在更多菜单，保留右键菜单作为辅助入口。
- 不把每行做成独立高阴影卡片。背景采用原生材料或系统语义背景，选中项有明确底色。

### 状态文案

| 状态 | 列表短标签 | 主动作 | 细节出现位置 |
| --- | --- | --- | --- |
| 已确认原生 | 已确认 | 打开 | 帮助/详情可见验证时间及目标版本 |
| 格式支持，尚未确认 | 待验证 | 验证 | 首次验证说明或选中项详情 |
| 原生路由未支持 | 暂不支持 | 说明 | 弹层说明保留入口、不会转到浏览器 |
| 打开失败 | 保持原验证状态或标重试 | 重试 | 单次错误提示与可展开详情 |
| 打开请求已被接收 | 待确认 | 确认结果 | 独立待确认区域，必须显示具体项目与入口 |

验证结果的可信性不能为了视觉简洁而弱化。系统接收打开请求仍然不等于进入了正确对话。用户确认必须绑定当前入口的 URL 与目标 App；新打开开始时清理旧待确认记录。

### 提示的体积

普通说明优先使用一行提示或点击后展开，避免每次选择云端入口就在主面板上方追加一大段文字。数据损坏、保存失败等阻断状态可以保留显著错误区域，但文案先说明发生了什么，再提供动作；技术细节放展开项。等待人工确认也可占独立区域，不能被普通 toast 自动覆盖。

## 个性化设置

采用即时生效并本地保存的设置。这里的「恢复默认」只恢复外观与行为偏好，不删除项目、入口或验证记录。

| 分组 | 控件 | 初始选择 | 验收 |
| --- | --- | --- | --- |
| 外观 | 系统 / 浅色 / 深色 | 系统 | 切换后主面板与设置窗口一致；系统模式跟随系统变化 |
| 外观 | 青绿 / 蓝 / 石墨 | 青绿 | 只影响选择、主动作与重点图标；语义状态不随主题变色 |
| 外观 | 标准 / 紧凑 | 标准 | 明显改变行高与间距，标题仍可读，点击目标不重叠 |
| 常规 | 登录时启动 | 以系统实际状态为准 | 实际注册、注销结果决定显示；异常可理解且可恢复 |
| 常规 | 呼出快捷键显示 | `⌃⌥Space` | 当前版本若不支持修改，只作说明，不伪装成可编辑控件 |

点缀参考：浅色青绿 `#245E70`，蓝 `#356C9A`，石墨 `#5A6470`。深色使用更亮的对应值，例如青绿 `#76B8C5`，并与系统背景检查对比度。固定深色文字不可复用到深色背景。未选中标题保持系统 primary；辅助文字用 secondary。

文字缩放、减少动态效果、增强对比度遵循系统选项。不要在泊岸里重复制造一套同名系统设置。菜单栏图标当前必须保留，避免快捷键冲突后失去入口。

## 登录启动：用户看到的真实状态

状态映射依据 [Apple SMAppService.Status](https://developer.apple.com/documentation/servicemanagement/smappservice/status-swift.enum)，下列中文文案是泊岸设计。

| 系统状态 | 显示文案 | 可用动作 |
| --- | --- | --- |
| `notRegistered` | 登录时启动：关闭 | 开启 |
| `enabled` | 登录时启动：已开启 | 关闭 |
| `requiresApproval` | 等待系统允许 | 打开登录项设置、取消注册 |
| `notFound` / 注册错误 | 尚未开启；显示具体失败原因 | 重试；必要时提示使用完整 App |

注册过程中显示忙碌并防止重复点击。设置窗口再次显示、从系统设置返回后重新读取状态。登录自启应只在菜单栏待命，不在用户刚登录时强行弹出主面板；正常手动启动则可显示面板。这是泊岸的行为选择，需要通过真实登录场景另行验收，不能仅靠状态读取声称已经验证。

## 发布与验收

公开 GitHub 的文档和截图仅展示虚构项目及入口。图片不可出现真实聊天标题、真实 UUID、账户名或私人目录；不提交运行时资料库、验证记录、日志和偏好文件。此项只约束展示内容，不改变用户本机资料。

实施完成后按下面的有限矩阵复核，不额外扩展产品范围：

- 标准与紧凑各一张主界面：能看到多个入口，状态没有挤掉名称，长标题不推挤按钮。
- 浅色与深色各一张：标题、辅助信息、选中行、状态标签与按钮都可读。
- 设置页：即时预览、重启后保留；恢复默认不影响入口资料。
- 键盘：呼出、搜索、范围切换后的选择、Return、按钮焦点和中文输入法都保持一致。
- 验证：待确认具体入口可识别；打开别的入口后旧确认不可误用。
- 登录启动：已开启/关闭/等待允许/错误均诚实显示；真正的重新登录验证独立记录。

当前文档是研究与设计规范，不代表以上功能均已实现或验收完成。
